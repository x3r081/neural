Neural · a local AI server for gpt-oss-120B

A 120-billion-parameter AI, running on one gaming PC.

Neural runs OpenAI's gpt-oss-120B, a model built for datacenter GPUs, on a single 12 GB graphics card plus 64 GB of RAM. It is private and fast enough to work with, and it plugs into coding tools like Continue in VS Code or Cursor.

The problem

The model is five times bigger than the graphics card.

AI models run fastest when all their weights sit in the graphics card's own memory. gpt-oss-120B takes 61 GB on disk, and a gaming graphics card has 12 to 32 GB (this PC's RTX 3080 Ti has 12). The usual fix is a datacenter GPU with 80 GB of memory, which most people rent in the cloud.

Neural's answer is to use the whole PC, with the graphics card and the processor each doing the part of the work it is best placed to do.

The trick

For any given word, most of the model rests.

gpt-oss-120B is a mixture of experts. Each of its 36 layers holds 128 small specialist networks, the experts. For every token, which is a word or a piece of one, a router picks the 4 experts that fit it best. The other 124 sit that token out.

One layer, one token: 4 of 128 experts do the work.

144experts used per token
4,608experts in the model
3%of the experts active at once

The catch: the picks change from token to token and are hard to predict. In tests, guessing ahead which experts come next never paid for itself. For code, the model calls on almost every expert it has within a couple of pages of output.

The split

Compute each expert where it already lives.

Graphics card

Holds the parts every token needs (attention and the router) plus the ~480 most-used experts. It is very fast, but only about 1 expert in 10 fits.

12 GB · 36 layers as CUDA graphs

~23 KBof messages per layer, instead of 13 MB per missing expert

Processor + RAM

All the other experts wait in RAM. When a token needs one, 8 CPU cores compute it right there, while the graphics card works on its own share at the same moment.

64 GB · AVX-512 · 21–30 GB/s

The usual way to split a model like this is by layer: some layers live on the card, and the CPU handles the experts of the rest. Neural splits it by expert instead. In every layer, the most-used experts sit on the card and the rest stay in RAM, and both sides work on each token at the same time. The other option, copying experts to the card as they are needed, is slow, because every missing expert is 13 MB. Neural moves the work to the data instead of the data to the work.

It adapts to your conversation. An expert that keeps coming up gets copied to the graphics card in the background, a few experts per token, while the CPU reads it anyway. The card's share of the work grows as the conversation goes on.

One token

What happens, layer by layer, for every token.

  1. The graphics card reads the conversation so far (attention), and the router picks 4 experts.
  2. Experts already on the graphics card are computed there.
  3. At the same moment, the CPU computes the others straight from RAM.
  4. The results are added up and passed on. After all 36 layers, the next token appears.

That whole loop runs 14 to 21 times a second when writing code, and faster for everyday text.

In short: by the fourth measurement on Sep 30 Neural read a 13,000-token prompt 13.9× faster than llama.cpp (6.8 s against 95.2 s), wrote follow-up answers 1.57× faster (1.11× on Sep 23, then 1.24, 1.34, 1.38, 1.54 and 1.54× through the day), and its first answer after the long prompt was 1.96× faster on the median, with individual runs from 1.84× to 2.08× (llama.cpp's own first answers ran slower this round, 10.9 to 12.8 tok/s against 13.3 to 13.6 earlier in the day, so the follow-up figure is the steadier one). The fourth step does the prompt maths in 64-row tiles instead of 16 (the graphics card was wasting three quarters of each tile) and prepares expert copies on a second thread, both bit-identical, and copies half as many experts into the card per answer at the same hit rate, which changes which experts the card keeps, so answers can differ from the previous version's the way they already differ between runs; earlier steps were layer-order prompt reading, a CPU kernel that reads RAM at the memory's ceiling, and a smaller expert store, all bit-identical. The file-rewrite figure stands at 1.42× from the first Sep 30 measurement: later attempts were not clean, because a rewrite starts on experts that other programs had pushed out of the PC's file cache, and reading them back from disk dominated its first tokens on every version tried. On Sep 24 the prompt figure was 3.1×, but the unchanged Sep 24 build also measured 6.5× on Sep 29, so the versions before Sep 30 (3) are not what made prompts faster then; why the PC got faster that week is not established. The model only just fits in 64 GB of RAM next to other programs, so the first answer still has to pull some experts from disk.

For coding

Plugs into your editor like a cloud model.

Neural speaks the OpenAI Chat Completions API. Point tools that use it at the server: Continue in VS Code or Cursor, the OpenAI SDKs, or your own scripts. Cursor's own built-in agent can't reach local models, and autocomplete (/v1/completions), the Responses API and images are not supported.

Limits

What it needs, and where it stops.

You need

  • Windows 10 or 11
  • An NVIDIA RTX 30-series or newer graphics card with 12 GB or more (tested on an RTX 3080 Ti), with an up-to-date driver (CUDA 13)
  • A CPU with AVX-512, such as an Intel 11th-gen Core, a Xeon W or Xeon Scalable, or an AMD chip with Zen 4 or newer cores (any Ryzen 7000 or 9000 desktop chip, or a laptop chip from the 7040 series on). Intel Core chips from 12th gen on lack it, and so do Ryzen 7020, 7030 and 7035 laptop chips.
  • 64 GB of RAM
  • About 120 GB free on an NVMe SSD

Good to know

  • One conversation at a time: it is a personal server, not a shared one.
  • Code arrives at 14–21 tokens per second. That is comfortable to read along with, but slower than cloud services.
  • Startup takes about 2 minutes.
  • Speed depends on free RAM, so close memory-hungry apps first.

Get started

Three steps to your own 120B model.

The code lives in a private GitHub repository for now, so ask me for access first. Then type these into Command Prompt (not PowerShell), all in the same window.

1. Get the code and its Python packages

git clone https://github.com/x3r081/NeuralServer.git
cd NeuralServer
py -3.12 -m venv .venv
.venv\Scripts\pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cu130

2. Download the model (61 GB) and build the expert store once

.venv\Scripts\hf download openai/gpt-oss-120b --exclude "original/*" --exclude "metal/*" --local-dir D:\Models\gpt-oss-120b
set NEURAL_MODEL_DIR=D:\Models\gpt-oss-120b
set NEURAL_STORE_DIR=D:\NeuralStores\gptoss120b_prepacked
.venv\Scripts\python tools\build_store.py

2b. Optional: pack the store (the Sep 30 numbers; same answers, less to read per token; needs another 55 GB of disk while both copies exist, then delete the first)

.venv\Scripts\python tools\pack_store.py --dst D:\NeuralStores\gptoss120b_ps4 --verify
set NEURAL_STORE_DIR=D:\NeuralStores\gptoss120b_ps4

3. Start the server, then connect your editor

.\start_neural_server.bat

The editor settings are under For coding above.

Questions

Fair questions.

Is this the full model, or a cut-down version?

It is the full gpt-oss-120B. OpenAI's published 4-bit expert weights are copied byte for byte into Neural's store. Nothing is re-quantized or pruned.

Does splitting the work change the answers?

The math is the same model. Neural's fast graphics-card code adds numbers in a slightly different order than the reference code, as GPU code generally does. Output quality was tested statistically, and the difference stays inside the spread the reference code itself shows when only its rounding order changes.

Why does RAM matter so much?

Every expert the CPU computes has to be read from RAM. Each token needs about 1.9 GB of expert weights in total, split between the graphics card and RAM. For code, the limit is how fast RAM can be read.

Why not just use llama.cpp?

llama.cpp is excellent and runs almost anywhere. On this PC, Neural reads long prompts 3–7× faster than llama.cpp, depending on the day it was measured. In a long coding conversation its follow-up answers were 1.34× faster and its first answer after the long prompt 1.16× faster (Sep 29). A research build answered short prompts 1.1–1.6× faster. Neural also adds features for coding agents: it replays its own tool calls exactly, so each step only reads the new result; it keeps the conversation cached when the editor sends side requests; and it prepares the next turn while you read.

Can I run it on a Mac or on Linux?

Not today. The server is built and tested on Windows with an NVIDIA card. The ideas carry over, but the code does not yet.

Where did this come from?

Neural began as a research project on running very large mixture-of-experts models on consumer hardware. It kept a detailed lab notebook, including the ideas that failed. This server is what came out of it.
